# 安卓实时程序雾：实现、参数与维护说明

更新：。适用工程：`apps/android/kuikly`，Kuikly 2.30.0-2.1.21，Kotlin 2.1.21，compileSdk 34 / minSdk 24。

本文件记录当前已实现的方式，以及从莫高窟实验迁移到其他皮肤后的分流。观感最终由用户在设备上确认；编译通过、日志推进只能证明代码运行，不能证明烟雾感好看。

## 1. 当前各皮肤采用什么

| --- | --- | --- |
| 黑白 bw | 实时程序雾，三色全部灰阶 | 程序生成的透明 PNG 动画回退 |
| 黑夜 hei | 实时程序雾，三色全部灰阶 | 透明 PNG 动画回退 |
| 梦幻 glass | 实时程序雾 | 透明 PNG 动画回退 |
| 宣纸 xuan | 实时程序雾 + 单独静止的纸纹 | 透明 PNG 动画回退 + 静止纸纹 |
| 青瓷 qing | 实时程序雾 | 透明 PNG 动画回退 |
| 豆沙 dou | 实时程序雾 | 透明 PNG 动画回退 |
| 敦煌 dh | 恢复实时实验前的原始 PNG 雾层 | 同左 |
| 莫高窟 mg | 恢复实时实验前的原始 PNG 雾层 | 同左 |
| 卡通 bru | 平面背景，不放雾 | 同左 |

“恢复没有实时雾气”指恢复旧的 PNG 路线，不是把所有雾都删除。敦煌/莫高窟使用原文件 `dh-ochre.png`、`dh-mineral.png`、`dh-azurite.png`、`mg-gold.png`、`mg-blue.png`、`mg-ember.png`，不读本轮生成的 `-flow` / `-wisp` 图。早先那一版为两层同图视差、90 秒时钟、非等比缩放，不旋转。旧开关仍可关闭运动、保留静态雾。

其余六套明确列在 `FogBackdrop.kt` 的 `REALTIME_FOG_SKINS` 中。将来新增皮肤不会因“不是卡通”而自动接入，需要显式加入。

## 2. 这个效果是什么、还不是什么

实时路径不加载雾的 PNG。安卓 RuntimeShader 在每次绘制时，针对每个输出像素计算透明度与颜色，输入包括像素坐标、尺寸、时间、皮肤色和随机种子。

位置、形状、浓淡和内部空隙都可随时间变化，不是仅把一张固定雾图移动、缩放。着色器中的第三维是时间演化坐标；最终仍绘制在一个二维背景上。

这叫实时程序雾或程序化烟雾视觉效果。没有求解速度场、压力、不可压缩条件、碰撞或质量守恒，因此不能称物理流体模拟。`relief` 产生的明暗也不是光源投射出来的真实阴影。不存在三维场景、真实体积光线步进或环境光散射。

## 3. 为什么没有直接在 Kuikly Canvas 里放 shader

本地 2.30.0 的 AAR 检查结果：

- Compose 的 Brush 公开的是线性、水平、竖直渐变，没有可直接套用 Android RuntimeShader 的 ShaderBrush。
- Paint 虽有 Object 类型 shader 属性，KuiklyCanvas 的填充路径实际转换成 CanvasLinearGradient 或纯色，不能由属性存在就断言能透传原生着色器。
- 宿主确有 `registerExternalRenderView` 和 `renderViewExport`；Compose 确有 `MakeKuiklyComposeNode`。因此走框架支持的原生自定义组件扩展，而不改 Kuikly 底层、不换 React/WebView、不引入另一套 Compose UI。

页面层不直接调用 Android 图形 API。系统版本检查放在 shared/androidMain；原生绘制放在 androidApp。注册发生在 MainActivity 原有 delegate 里，不改变 IME、震动、更新和判据逻辑。

调用链：

```text
RootScreen
  → SkinBackdropLayer → key(skinKey)
    → SkinFogBackdrop
      → SDK >= 33 且在六套白名单中
        → RealtimeFog → MakeKuiklyComposeNode
          → RealtimeFogNode(viewName = XLRRealtimeFog)
```

## 5. 每帧的生成过程

### 5.1 平滑噪声与浓度

`hash(float3)` 把空间网格坐标映射到确定性的伪随机值。同一个坐标和种子得到同一个值，不每帧随机闪烁。

`noise3` 对单元格的八个角做三线性插值，并用五次平滑曲线 `6f^5 - 15f^4 + 10f^3` 处理插值进度，让跨单元格时的一、二阶变化连续。

最初的密度仅低频平滑，会出现大片近圆形色岛，看起来仍像椭圆。当前 `smoke` 先旋转坐标，再用两股连续噪声扭曲坐标，叠加少量不同尺度的浓度（0.57、0.28、0.11、0.04），再局部扣去一部分密度形成分叉和空隙。不会对雾边缘描线。

### 5.2 全屏随机游走

`wander(seconds, period, id)` 将时间分成若干段，为相邻时间段计算两个伪随机目的地，用同一五次曲线连接。

- 三股独立雾的换向周期：26 / 31 / 29 秒。
- 第二、第三股分别加 7 / 15 秒初始错相。
- 每个 FogSurface 创建时使用一个随机 seed；重进页面或换肤重建后初始分布可不同。
- 返回值大致落在 -1.2 到 +1.2，随后按画面宽高比与空间尺度放大，游走范围覆盖视口尺度。
- 这里移动的是密度场采样位置，不是固定圆形物体的中心。中间、边角都可以出现浓区，但没有“必须依次到达四个角”的巡航脚本。
- 随机方向平滑变化；不每帧 random，不突然跳位置，也没有固定正弦轨道循环。

`time * 0.045` 同时控制雾内部演化；线性采样偏移继续提供基础流向。随机游走和内部演化相互独立，所以既会换地方，也会改变自身形状。

### 5.3 颜色、透明度、暗部

三股雾浓度经 smoothstep，再平方，形成柔软但可辨识的浓区与空隙。颜色按三股浓度加权。第三股浓度乘 0.72，避免三种颜色总是等量混成均匀底色。

总透明度为：

```text
total = a + b + c + 0.001
alpha = strength * (1 - exp(-1.15 * total))
color = (color1*a + color2*b + color3*c) / total
```

浓处根据另一层低频噪声做约 8–20% 的同色暗化（由 core 连续控制，并非每处都达到这个值）。它在雾的内部变化，不画在边缘外侧，避免色块像浮起来。

返回 `half4(color * alpha, alpha)`，使用预乘透明颜色，供 Android 正常合成。不能省掉 RGB 乘 alpha，否则透明边可能亮边或色彩错误。

当前接入的六套实时雾都启用 `relief = 1`，即上述不规则形态、随机游走、内部暗部；这名字沿用早期试验，不代表物理浮雕。

| 黑白 | #242424 | #FFFFFF | #888888 | 0.16 |
| 黑夜 | #ACACAC | #686868 | #959595 | 0.18 |
| 梦幻 | #DF9EC4 | #94B5EB | #B497DB | 0.33 |
| 宣纸 | #C0A587 | #B8AA97 | #C8B89F | 0.10 |

全局参数：

| 参数 | 当前值 | 调整影响 |
| --- | --- | --- |
| tick 调度间隔 | 33ms | 约 30 次/秒的调度目标，不是实测帧率保证 |
| 逻辑时间 | 实际经过的秒数 | 不用帧数累加，掉帧不会让动画节奏变慢 |
| 时间缩放 | 0.045 | 增大会加快内部形变及基础流向 |
| 空间尺度（relief=1） | 4.6 | 增大会增加画面内结构数量，过大容易碎、皱 |
| 第一层共享扭曲 | 1.20 | 降低趋向圆滑色岛，过高容易密集褶皱 |
| smoke 内部扭曲 | 1.10 | 控制边缘分叉、曲折 |
| 密度阈值 | 0.26–0.72 | 收窄会突出边缘但更实；拉宽会柔，但容易均匀铺色 |
| breaks 扣除密度 | 0.13 | 增大会多空隙，过高会碎裂 |
| 第三股相对浓度 | 0.72 | 控制第三种颜色的面积/参与度 |

建议一次只动一个视觉点，先确认变化原因再继续。

## 7. 怎样调，避免再次踩坑

- **整体太浓**：先降该皮肤 strength。不要同时大幅改颜色、阈值与速度。
- **颜色太淡但浓度已合适**：提高雾色本身的彩度，控制覆盖率；别直接把所有 alpha 拉高。黑白/黑夜必须保持灰阶。
- **像椭圆**：检查空间尺度、是否已启用 smoke 和 wander、坐标扭曲是否太弱。只有低频平滑噪声会形成近圆色岛，即使没有画椭圆也会像椭圆。
- **褶皱密集、像布或大理石**：减少高频噪声权重与扭曲强度；避免窄带等高线、急阈值和过大的空间尺度。
- **移动局促**：优先检查 wander 的 travelScale 与幅度，不仅是 time 速度。扩大移动范围不等于加速。
- **看不出形变**：确认不是 PNG 路线；确认 motion=true、time 递增；随后拉开浓淡、增加空隙和局部扭曲。日志不是观感验收。
- **色彩发灰/发脏**：先看皮肤底色、雾色和卡面的关系。三股色等量混合可能近似灰，不应继续用更多颜色补救。
- **像硬色块**：保留宽的平滑过渡，不给边缘加暗描边或投影。

## 8. 开关、生命周期和触摸

`Skin.fogMotion` 为唯一动效开关，持久化键 `K_FOG_MOTION`。属性以 fogMoving 传给原生层。

- 关闭时停止 tick，保留当前 phaseSeconds，显示静态帧。
- 重新打开时将 previousNanos 清零，第一步不计入暂停期间经过的时间，避免突然跳进度。
- attach、可见性变化时重启检查；detach 时移除 tick。
- tick 检查 isAttachedToWindow、isShown、windowVisibility、moving 与 shader 是否有效。
- 当前没有独立接入 Activity 的 onPause；主要依赖 View 可见性/挂载状态。特殊多窗口场景应另行检查，不声称所有后台状态都已测过。
- RealtimeFogAttr.touchEnable(false)，原生 dispatchTouchEvent 返回 false；雾层不拦截输入框、点击或滑动。
- 隐藏无障碍焦点，避免背景图形进入阅读顺序。
- 换肤由 key(skinKey) 重建，旧 View 脱离时停止时钟；新 View 使用新种子，从自己的初始相位开始。

## 9. 兼容、故障与性能边界

RuntimeShader 自 Android 13/API 33 起提供。当前只是检查系统版本，不是全 GPU 驱动能力探测。旧系统回退 PNG；不提高 minSdk。

Shader 构造失败会记录 XLRFOG 编译错误并使 shader=null。当前行为是保留页面底色，不绘制雾；尚未实现“编译失败后自动通知 shared 改走 PNG”。这与“系统版本低时自动回退 PNG”是两个不同情况。

33ms postDelayed 是调度目标，实际频率受主线程与系统合成影响。Shader 绘制按实际 View 尺寸执行，目前没有降分辨率渲染器。噪声层和全屏像素数都影响 GPU 开销；不要声称只是一个矩形就无成本。

已在 API 35 模拟器验证过 1080×2412 hardware=true，换肤与触摸可用。模拟器结果不代表实机功耗、发热或老 GPU；未做实机长时耗电验收。后续有性能问题应减少采样、降低调度频率或加低分辨率绘制，不要让全部数学计算改到每像素 CPU 循环。

full / lite 使用相同背景实现，没有新增 lite 分支，不涉及判断依据卡或提示词。

## 13. 完整 AGSL（当前实现快照）

下列程序直接来自 RealtimeFogView.kt 的 SOURCE。正式唯一运行源是该 Kotlin 文件；修改着色器后应同步更新此快照。

```glsl
uniform float2 resolution;
uniform float time;
uniform float3 color1;
uniform float3 color2;
uniform float3 color3;
uniform float strength;
uniform float relief;
uniform float seed;

float hash(float3 p) {
    p = fract(p * 0.1031);
    p += dot(p, p.yzx + 33.33);
    return fract((p.x + p.y) * p.z);
}
float noise3(float3 p) {
    float3 i = floor(p);
    float3 f = fract(p);
    f = f*f*f*(f*(f*6.0-15.0)+10.0);
    return mix(
        mix(mix(hash(i), hash(i+float3(1,0,0)), f.x),
            mix(hash(i+float3(0,1,0)), hash(i+float3(1,1,0)), f.x), f.y),
        mix(mix(hash(i+float3(0,0,1)), hash(i+float3(1,0,1)), f.x),
            mix(hash(i+float3(0,1,1)), hash(i+float3(1,1,1)), f.x), f.y), f.z);
}
float density(float3 p) {
    return 0.76*noise3(p) + 0.19*noise3(p*1.93+5.7)
         + 0.05*noise3(p*3.71+13.1);
}
// Independent random destinations, smoothly joined: no orbital loop,
// no per-frame random flicker. Travel spans the viewport, not a corner.
float2 wander(float seconds, float period, float id) {
    float segment = floor(seconds/period);
    float f = fract(seconds/period);
    f = f*f*f*(f*(f*6.0-15.0)+10.0);
    float2 start = float2(hash(float3(segment,id,seed)),hash(float3(segment,id+9.7,seed)));
    float2 finish = float2(hash(float3(segment+1.0,id,seed)),hash(float3(segment+1.0,id+9.7,seed)));
    return (mix(start,finish,f)-0.5)*2.4;
}
float smoke(float3 p) {
    if (relief < 0.5) return density(p);
    // Rotated coordinates and independently warped interiors break
    // smooth round islands into branching, dissolving concentrations.
    p.xy = float2(p.x*0.86-p.y*0.51,p.x*0.51+p.y*0.86);
    float2 curl = float2(noise3(p*1.1+3.7),noise3(p*1.1+9.2))-0.5;
    p.xy += curl*1.1;
    float broad = 0.57*noise3(p) + 0.28*noise3(p*1.87+5.7)
                + 0.11*noise3(p*3.4+13.1) + 0.04*noise3(p*5.8+21.3);
    float breaks = noise3(float3(p.xy*2.1,p.z*0.7+17.4));
    return broad - 0.13*smoothstep(0.45,0.8,breaks);
}
half4 main(float2 coord) {
    float2 uv = coord / resolution.y;
    float t = time * 0.045;
    float2 p = uv * mix(3.2,4.6,relief);
    float2 bend = float2(
        noise3(float3(p*0.7+2.1,t*0.6)),
        noise3(float3(p*0.7+8.3,t*0.6+4.2))) - 0.5;
    // A broad evolving current, without high-frequency folds.
    p += bend * (0.65 + 0.55*relief);
    p += relief*0.16*float2(sin(p.y*1.6+t*0.9),sin(p.x*1.4-t*0.7));
    float lo = mix(0.22,0.26,relief);
    float hi = mix(0.86,0.72,relief);
    float2 travelScale = float2(resolution.x/resolution.y,1.0)*4.6;
    float2 wa = relief*wander(time,26.0,1.3)*travelScale;
    float2 wb = relief*wander(time+7.0,31.0,8.9)*travelScale;
    float2 wc = relief*wander(time+15.0,29.0,17.2)*travelScale;
    float a = smoothstep(lo,hi,smoke(float3(p-wa+float2(t*0.55,-t*0.35),t)));
    float b = smoothstep(lo,hi,smoke(float3(p*0.87-wb+float2(5.4-t*0.40,2.6+t*0.28),t+7.3)));
    float c = smoothstep(lo+0.04,hi+0.02,smoke(float3(p*0.72-wc+float2(9.2+t*0.32,6.1-t*0.20),t*0.8+15.7)));
    // Broad soft concentrations with clear gaps: avoid an even pastel wash.
    a *= a;
    b *= b;
    c *= c;
    c *= mix(1.0,0.72,relief); // Warm ochre remains a smaller supporting current.
    float total = a+b+c+0.001;
    float alpha = strength * (1.0-exp(-1.15*total));
    float3 color = (color1*a+color2*b+color3*c)/total;
    // Same-hue darkening INSIDE dense fog, never an outline/drop shadow.
    float core = smoothstep(0.30,1.25,total);
    float depth = noise3(float3(p*0.8+4.7,t*0.85+3.1));
    color *= 1.0-relief*core*(0.08+0.12*depth);
    return half4(color*alpha,alpha);
}
```

## 17. 开关拖动状态修复

复现：进入设置时动效为关闭；向右拖动开启成功，再向左拖动时拨钮视觉回到关闭，但没有 motion=false，雾仍运行。根因是 GlassSwitch 的 pointerInput(Unit) 手势协程跨重组保留，捕获首次 checked；第二次拖动目标等于旧值时不调用 onChange。使用 rememberUpdatedState 同时读取最新 checked 与 onChange；取消拖动也读取最新状态。实时渲染器、雾色、浓度、形变和速度不变。开关停止的是运动，保留静态雾色。

修复验证：assembleDebug 成功并安装。模拟器同一设置会话连续拖动得到 motion=false → true → false；普通行点击得到 motion=true → false；后续页面重建读取到 motion=false。三项判据自检全部 PASS。当前保留关闭状态供用户确认静态雾，未打正式包。

## 新增：二/三档独立「冻」按钮与雾图细节

用户最终指定：在二档「轻柔流动」和三档「实时流雾」各放一个小「冻」按钮，点亮为冻结，再点熄灭继续。一档无冻按钮。点击某档冻按钮会选中对应档位并切换该档冻结状态；两档分别记忆，互不覆盖。卡通仍不画雾、不显示冻按钮。

### 改动与保存

- Skin.kt：K_FOG_FROZEN_1 / K_FOG_FROZEN_2 分别保存二/三档状态；K_FOG_PHASE_<skin> 保存 PNG 相位。旧实验 K_FOG_FROZEN 不再读。配置均使用现有 Platform 存储桥。
- SettingsText.kt：FogFreezeButton(level)，24dp 圆玻璃按钮，主色边与淡底点亮，220ms 非线性反馈。选择器原有拖拽形变保留。
- FogBackdrop.kt：PNG 改成一份共享 Animatable 驱动各雾层，停止时取消动画协程并保存当前相位；继续时从当前相位跑完剩余周期，不跳回零。切肤/切档也保存相位，重启冻住的 PNG 恢复原相位。
- RealtimeFogView.kt：fogMoving=false 时取消 33ms tick，冻结 phaseSeconds。后台单线程用公开 HardwareRenderer + RenderNode + ImageReader 一次性渲染透明位图（长边最多 2048px），完成后 onDraw 只 drawBitmap，paint.shader=null，不再执行 AGSL 雾形计算。解冻移除位图，重新挂回 shader，从原相位继续；不把冻结期间经过的时间补进去。
- 快照任务带版本号，换皮肤/解冻/布局尺寸变化/移除视图会使旧任务失效，旧结果不会覆盖当前画面。离开视图取消 tick，旧快照释放引用交给 GC，避免回收仍被 RenderThread 引用的已显示位图。
- 原生私有 xlr_fog_frames 配置只保存每套皮肤的随机 seed 与冻结 phase。当前快照在内存，不写 PNG 文件；冷启动恢复第三档冻结画面需要一次重建，此后静态显示。不是永久零内存/零绘制：仍有位图内存和正常显示合成成本，但无持续雾动画或每帧雾形生成。
- 极少数设备离屏快照失败会记 XLRFOG 错误，时钟仍停止；此降级仍可能在外部重绘时计算固定相位 shader。模拟器已确认快照成功，未伪称所有实机都验证。
